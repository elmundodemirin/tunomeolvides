01. Bienvenida y contexto

No Me Olvides es una plataforma web bilingüe (con UI también en francés) cuyo elemento central es un mapa interactivo de España donde cada punto representa una localidad rural documentada con un audio narrado en primera persona. La promotora del proyecto es María del Carmen López Rosa, que gestiona todo el contenido de forma autónoma desde el panel /admin.

El objetivo del proyecto es preservar la memoria oral del patrimonio cultural de la España vaciada haciéndolo accesible a cualquier visitante con conexión a internet, sin login, sin registro y cumpliendo RGPD desde el día 1. La Fase 1 (que es la que has heredado) está prácticamente completa: faltan los bloques B8 (SEO técnico), B9 (documentación final) y B10 (testing y optimización Lighthouse).

Este documento va dirigido a ti, programador o programadora que toma el relevo. Su intención es ahorrarte el medio día de arqueología que normalmente cuesta entender un proyecto ajeno: aquí tienes los accesos, las decisiones tomadas, las trampas que ya conozco y los puntos donde más dolería romper algo. Léelo entero antes de tocar nada y, cuando empieces a hacer cambios, mantenlo vivo: es la única forma de que el siguiente que venga detrás de ti tenga la misma cortesía.

02. Stack y arquitectura en una página

El stack es deliberadamente estándar y popular: cualquier programador moderno debería poder ponerse al día sin reescribir nada. Sin abstracciones propietarias, sin frameworks exóticos.

Cómo encajan las piezas

La aplicación tiene dos vidas paralelas dentro de la misma codebase Next.js:

  • Web pública (rutas /[locale]/...): visitante anónimo, mapa interactivo, popups con audios, formulario de contacto, páginas estáticas (sobre, contacto, legales). 100% sin login.
  • Panel admin (rutas /admin/...): autenticado con Supabase Auth. CRUD de localidades (incluida subida de audios MP3), gestión de mensajes de contacto, e invitación de nuevos administradores.

El idioma por defecto es español; inglés y francés están soportados como UI traducida. Las descripciones y audios solo existen en ES y EN: si el visitante navega en FR, el contenido cae a EN como fallback automático (pickLocalized()).

04. Cómo arrancar el proyecto en local

  1. Clona el repo: git clone git@github.com:aitorsotorubio/nomeolvides.git
  2. Entra en la carpeta y ejecuta npm install.
  3. Copia .env.example a .env.local y rellena los valores reales (los obtienes del dashboard de Supabase y del proyecto en Vercel).
  4. Arranca el servidor de desarrollo con npm run dev. Abre http://localhost:3000.
Next.js 16 = Turbopack por defecto

Desde Next.js 16, el comando next dev usa Turbopack sin configuración explícita. Es notablemente más rápido que el viejo Webpack en arranque y en recarga, pero algunos plugins antiguos pueden no ser compatibles. Si añades una dependencia y rompe el dev server, comprueba primero si tiene soporte Turbopack.

05. Despliegue

Vercel está conectado al repositorio de GitHub. El flujo es completamente automático:

  • Cada push a main dispara un build de producción y despliegue inmediato.
  • Cada pull request genera un preview deploy con su propia URL temporal — útil para validar cambios antes de mergear.
  • Los rollbacks se hacen desde el dashboard de Vercel (Deployments → Promote previous).

Variables de entorno en Vercel

Se configuran en Vercel → Settings → Environment Variables. Cada variable se define para uno, dos o los tres entornos:

  • Production — el sitio en vivo.
  • Preview — los deploys de pull requests.
  • Development — para vercel dev en local (no se usa habitualmente; nosotros usamos npm run dev con .env.local).
⚠ Tras añadir o cambiar una variable: Redeploy

Las variables de entorno se inyectan en build time, no en runtime. Si cambias una variable y no haces Redeploy del último build (Deployments → ... → Redeploy), el cambio NO se aplicará. Es una de las causas más comunes de "lo cambié pero sigue fallando".

06. Supabase: configuración crítica

Supabase es el backend completo (BBDD + Auth + Storage). Tres bloques de configuración importan especialmente:

Region

El proyecto está en eu-central-1 (Frankfurt). Esto es requisito legal: los datos personales (mensajes de contacto, emails de admins) deben quedarse en territorio UE para cumplir RGPD sin tener que firmar cláusulas contractuales tipo (CCT) ni complicar el registro de actividades de tratamiento. Si por lo que sea hay que mover el proyecto a otra región, tiene que ser otra región UE.

Authentication → URL Configuration

En el dashboard de Supabase, en Authentication → URL Configuration:

  • Site URL: https://nomeolvides.vercel.app (o el dominio definitivo cuando se compre).
  • Redirect URLs (lista permitida): debe incluir https://nomeolvides.vercel.app/** y http://localhost:3000/** al menos. Y la URL del dominio definitivo cuando esté.
⚠ Sin esto, los emails de invitación rompen

El flujo de invitación de nuevos admins (ver §09) genera un email con un enlace que vuelve a la app. Si la URL de retorno no está en la lista de Redirect URLs permitidos, Supabase rechaza el redirect y el invitado no puede entrar. Es uno de los errores que más se repiten al cambiar de dominio.

Storage bucket audios

  • Lectura pública (los audios deben oírse sin login).
  • Escritura solo autenticada (la promotora y los admins).
  • Tamaño máximo por archivo: 10 MB.
  • Estructura de rutas: audios/{locality_id}/{es|en}.mp3.

Row Level Security (RLS)

Activado en localities y contact_messages. Las políticas están versionadas en supabase/migrations/. Resumen:

  • localities: lectura pública de las que tienen active = true; escritura solo para autenticados.
  • contact_messages: cualquiera puede insertar (formulario de contacto público); leer / actualizar / borrar solo admins.

Para más detalle ver 01_arquitectura.html §04.

07. Migraciones de base de datos

Las migraciones SQL están versionadas en supabase/migrations/ con el formato YYYYMMDD_descripcion.sql. Hasta hoy hay una:

  • 20260502_contact_messages_handled.sql — añade los campos de auditoría (updated_at, handled, handled_at, handled_by, admin_notes) a contact_messages y las políticas RLS necesarias para que el panel pueda actualizar y borrar.

Cómo aplicar una nueva migración

  1. Crea un nuevo fichero en supabase/migrations/ con el formato de fecha.
  2. Escribe el SQL idempotente cuando sea posible (IF NOT EXISTS, CREATE OR REPLACE).
  3. Pega el contenido en Supabase Dashboard → SQL Editor → Run.
  4. Commitea el fichero .sql al repo: la migración queda versionada para futuras instalaciones (clonar a otro proyecto, recrear en local, etc.).
⚠ Operaciones destructivas: avisa siempre

Cualquier DROP TABLE, DROP COLUMN, TRUNCATE o similar debe avisarse a la promotora antes de ejecutar — los datos de las localidades son patrimonio recopilado a mano y perderlos sería un desastre. Supabase pide confirmación explícita en el editor SQL para estas operaciones.

Para los triggers prefiere CREATE OR REPLACE TRIGGER (Postgres 14+) en lugar de DROP TRIGGER IF EXISTS + CREATE TRIGGER: evita el aviso destructivo y es atómico.

09. Flujo de invitación de admins

El panel admite múltiples administradores. La promotora (o cualquier admin existente) puede invitar a otros sin tocar Supabase. El flujo completo:

  1. Un admin actual entra en /admin/usuarios, escribe un email y clica "Enviar invitación".
  2. La UI llama al endpoint POST /api/admin/users (en app/api/admin/users/route.ts). El handler valida que el caller está autenticado y construye la URL de retorno: 
    const siteUrl =
  process.env.NEXT_PUBLIC_SITE_URL ?? new URL(request.url).origin

await admin.auth.admin.inviteUserByEmail(email, {
  redirectTo: `${siteUrl}/admin/set-password`,
})
    El cliente admin usa la SUPABASE_SERVICE_ROLE_KEY, por eso solo puede invocarse desde el servidor.
  3. Supabase envía un email a la dirección invitada con un enlace. Al pulsarlo, el navegador llega a /admin/set-password con la sesión de la persona ya activa (token en el hash de la URL).
  4. La página /admin/set-password recoge una contraseña, llama a auth.updateUser({ password }), y al guardarla la persona queda autenticada como admin. Ya puede entrar al panel con email + contraseña.
📌 Por qué el redirectTo explícito

Sin el parámetro redirectTo, Supabase usaría el "Site URL" configurado en el dashboard. Eso funciona en producción siempre que el Site URL esté bien, pero rompe en preview deploys de Vercel y en local. Pasarlo explícitamente desde NEXT_PUBLIC_SITE_URL (con fallback al origin del request) hace la app independiente del Site URL del dashboard y multientorno por construcción.

10. Backups y operativa

Backups de Supabase

  • El plan Free de Supabase incluye backups diarios automáticos con retención limitada. Verifica el plan vigente al hacerte cargo: si el proyecto sube a Pro, la retención de backups aumenta y se pueden hacer point-in-time recovery.
  • A día de hoy no hay backups automáticos extra fuera de Supabase. Es razonable configurar un dump semanal a almacenamiento externo (GitHub Action programado + bucket S3 de terceros, por ejemplo). Recomiendo hacerlo cuando el proyecto pase a producción real con visitantes.

Audios

Viven en Supabase Storage (bucket audios). Para descargarlos masivamente — útil antes de una migración o como copia de seguridad — usa la CLI de Supabase: 

# Listar todos los archivos del bucket
supabase storage ls ss:///audios --recursive

# Descargar el bucket completo a una carpeta local
supabase storage download ss:///audios ./backup-audios --recursive

Política de retención de mensajes

Los contact_messages deben borrarse automáticamente a los 2 años desde su recepción (decisión legal documentada en 03_lopd_compliance.html). El cron job que lo haga está pendiente de implementar — ver 01_arquitectura.html §05. Hasta que esté operativo, conviene revisar manualmente cada cierto tiempo si hay mensajes con más de 2 años y borrarlos.

11. Cosas raras / decisiones a recordar

Esta es la sección de "ojo con esto". Cosas que ya rompieron una vez y que conviene saber antes de tocar el código.

Leaflet y los z-index

El contenedor del mapa lleva isolation: isolate en CSS. Leaflet usa internamente capas con z-index entre 200 y 700, y sin aislamiento esas capas peleaban contra el header sticky y, sobre todo, contra el dropdown del selector de idioma (que terminaba pasando por debajo del mapa). El isolation: isolate crea un nuevo stacking context local: Leaflet se queda dentro de su mundo y el dropdown vive en el mundo de fuera, sin interferir.

La sesión en /admin/set-password llega por hash

Cuando el invitado pulsa el enlace del email, Supabase no usa cookies ni query params: el token de sesión llega en el fragmento de la URL (todo lo que va después del #). El cliente browser de @supabase/ssr lo detecta automáticamente al llamar a getSession() o al suscribirse a onAuthStateChange. No hay que parsear el hash a mano. Si en algún momento esa página deja de funcionar, sospecha primero de este detalle.

Idioma FR sin contenido propio

Las descripciones y los audios siguen siendo solo ES + EN. El francés muestra la UI traducida (botones, textos del header, mensajes del formulario, etc.) pero el contenido de las localidades cae a EN como fallback vía pickLocalized(). No añadas columnas description_fr ni audio_url_fr sin hablarlo antes con la promotora: significa traducir y grabar todo.

Migración a Next.js 16: proxy.ts en lugar de middleware.ts

Desde Next.js 16, el archivo de middleware se llama proxy.ts y la función exportada es proxy() en lugar de middleware(). No es renombrado libre: Next 16 obliga a este nombre. Si abres documentación o ejemplos viejos verás middleware.ts; tradúcelo mentalmente. La firma de la función y el objeto config con el matcher siguen siendo idénticos.

Charset y finales de línea (Windows)

El proyecto se desarrolla en Windows pero el repo se commitea con finales de línea LF. Asegúrate de que tu editor está configurado para no convertir a CRLF al guardar (en VS Code: Files: Eol = \n). Si git status te marca diffs gigantes en archivos que no has tocado, casi siempre es por CRLF/LF.
