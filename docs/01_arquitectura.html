Arquitectura técnica de nomeolvides.es

Proyecto No Me Olvides · Patrimonio cultural de la España vaciada
Última actualización: 24 de septiembre de 2026

01. Resumen ejecutivo

nomeolvides.es es una plataforma web bilingüe (ES/EN) cuyo elemento central es un mapa interactivo de España donde cada punto representa una localidad documentada del patrimonio rural. Al pinchar un punto, el visitante accede a un audio narrado y a información de la localidad.

La plataforma incluye un panel de gestión autónomo que permite a la promotora (María del Carmen López Rosa) añadir, editar y desactivar localidades sin tocar código, así como subir archivos de audio directamente desde el navegador.

Principios rectores del proyecto
  • Autonomía: la promotora gestiona el contenido sin depender del programador.
  • Portabilidad: stack estándar para que cualquier programador pueda continuar el trabajo.
  • Bajo coste: tecnologías open source y servicios con free tier suficiente para empezar.
  • Cumplimiento LOPD: la web cumple RGPD desde el día 1, no como añadido posterior.
  • Documentación viva: todo cambio relevante queda reflejado en HTML autocontenido.

02. Arquitectura

Arquitectura de tres capas claramente separadas: frontend (Next.js sobre Vercel), backend gestionado (Supabase: PostgreSQL + Auth + Storage) y servicios externos (mapa con OpenStreetMap, analítica con GA4, SMTP transaccional vía Resend). El dominio tunomeolvides.es y sus registros DNS se gestionan en Hostinger, apuntando a Vercel.

Flujo del visitante

  1. El visitante entra en nomeolvides.es.
  2. Vercel sirve la página con el mapa renderizada en el servidor (SSR) — buena para SEO y velocidad inicial.
  3. Leaflet pide los tiles del mapa a OpenStreetMap.
  4. Next.js consulta a Supabase la lista de localidades activas y las pinta como puntos.
  5. Al pinchar un punto, se carga el popup con datos y se reproduce el audio servido por Supabase Storage.

Flujo de la promotora

  1. Accede a nomeolvides.es/admin e inicia sesión con email + contraseña (Supabase Auth).
  2. Ve un listado de localidades, puede crear, editar, desactivar o eliminar.
  3. Sube archivos MP3 que se almacenan en Supabase Storage.
  4. Los cambios se reflejan inmediatamente en la web pública.

⚖ Política de retención obligatoria

Los mensajes de contacto se conservan un máximo de 2 años desde su recepción. Pasado ese plazo se eliminan automáticamente mediante un cron job en Supabase. La promotora puede borrar manualmente cualquier mensaje en cualquier momento desde el panel.

Bucket de Supabase Storage: audios

  • Estructura: audios/{locality_id}/es.mp3 y audios/{locality_id}/en.mp3.
  • Acceso público de lectura (los audios deben oírse sin autenticación).
  • Subida restringida a usuarios autenticados (la promotora).
  • Tamaño máximo por archivo: 10 MB (suficiente para 5-10 minutos de audio comprimido).

Trigger reusable set_updated_at()

Función única que mantiene updated_at al día en cada UPDATE. Se aplica a las dos tablas para evitar tener que tocar este campo desde la aplicación. 

-- Función reusable
CREATE OR REPLACE FUNCTION set_updated_at()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- Aplicada a localities
CREATE TRIGGER trg_localities_updated_at
  BEFORE UPDATE ON localities
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();

-- Aplicada a contact_messages
CREATE TRIGGER trg_contact_messages_updated_at
  BEFORE UPDATE ON contact_messages
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();

Seguridad: Row Level Security (RLS)

Supabase permite reglas de seguridad a nivel de fila. Las políticas que se aplicarán: 

-- Cualquiera puede LEER localidades activas
CREATE POLICY "public_read" ON localities
  FOR SELECT USING (active = true);

-- Solo usuarios autenticados (la promotora) pueden modificar
CREATE POLICY "admin_write" ON localities
  FOR ALL USING (auth.role() = 'authenticated');

-- Mensajes de contacto: solo escritura pública, lectura solo admin
CREATE POLICY "public_insert" ON contact_messages
  FOR INSERT WITH CHECK (true);
CREATE POLICY "admin_read" ON contact_messages
  FOR SELECT USING (auth.role() = 'authenticated');

-- Sin estas dos políticas, marcar atendido o borrar mensajes fallaba por RLS
CREATE POLICY "admin_update" ON contact_messages
  FOR UPDATE USING ((select auth.role()) = 'authenticated');
CREATE POLICY "admin_delete" ON contact_messages
  FOR DELETE USING ((select auth.role()) = 'authenticated');

05. Cumplimiento LOPD/RGPD

Como responsable de tratamiento, No Me Olvides debe cumplir el RGPD (UE) y la LOPDGDD (España). Este apartado lista todas las obligaciones que impactan el desarrollo.

⚠ Datos personales que la web tratará
  • Email + nombre + mensaje del formulario de contacto.
  • Email + contraseña hashed de la promotora (cuenta del panel).
  • Cookies analíticas de Google Analytics 4 (con consentimiento previo).
  • Datos de navegación recogidos por GA4 (IP anonimizada, dispositivo, idioma…).

⚖ Trazabilidad de mensajes atendidos (RGPD art. 5.2)

Cada mensaje de contacto que se marca como atendido registra quién (handled_by → auth.users.id) y cuándo (handled_at). Esto refuerza el principio de responsabilidad proactiva (accountability) del RGPD art. 5.2: ante una solicitud de la AEPD o del propio remitente, se puede demostrar quién trató cada mensaje y en qué fecha. Las notas internas (admin_notes) NO son visibles para el remitente y solo deben usarse para anotaciones operativas, nunca para datos personales sensibles.

⚖ Email transaccional dentro de la UE

Los emails transaccionales del panel (invitación de nuevos administradores y recuperación de contraseña) se envían a través de Resend, cuyos servidores SMTP están en EU-West (Dublín). Los metadatos del envío (direcciones, asuntos, fechas) se procesan y almacenan en territorio UE, en coherencia con la base de datos de Supabase en Frankfurt. No se produce, por tanto, transferencia internacional de datos personales para este canal de comunicación.

📌 Transferencia internacional (GA4)

Google Analytics transfiere datos a EE.UU. Para minimizar riesgo legal:

  • Usar GA4 con anonimización de IP y consentimiento previo (no Universal Analytics).
  • Mencionar explícitamente en la política de cookies la transferencia internacional.
  • Firmar el DPA de Google (se acepta digitalmente al crear la cuenta).

Recomendación a futuro: evaluar migración a Plausible o similar para eliminar esta complejidad legal. Decisión aplazada por la promotora.

Posibles costes futuros

  • Vercel Pro (20 $/mes): necesario si se supera 100 GB de tráfico mensual. Improbable en Fase 1.

⚠ Limitación del free tier de Supabase

Los proyectos en plan Free se pausan tras 7 días sin actividad. Esto NO es problema en producción (siempre habrá visitas), pero sí durante desarrollo si hay parones de varias semanas. Para minimizar el riesgo, el desarrollo se hará en sprints continuos sin parones largos.

10. Siguientes pasos

El setup técnico está completo y desplegado en https://tunomeolvides.es. Quedan estas piezas pendientes, de mayor a menor prioridad:

10.1 — B8: SEO técnico ✅ Completado (2026-09-10)

  1. Metadatos dinámicos por página: lib/seo.ts centraliza título, descripción, Open Graph y alternates (canonical + hreflang es/en/fr) por página. Home, "Sobre" y "Contacto" usan generateMetadata() con next-intl (namespaces home/about/contact, claves metaTitle/ metaDescription); las 9 páginas legales (aviso, privacidad, cookies × 3 idiomas) usan export const metadata estático, ya que su contenido también está escrito directamente por idioma. El layout raíz define metadataBase y un title template (%s · No Me Olvides).
  2. Sitemap.xml automático (app/sitemap.ts): enumera las 6 páginas estáticas (Home, Sobre, Contacto, 3 legales) en los 3 idiomas, con alternates.languages por entrada. No incluye localidades individuales — ver nota más abajo.
  3. robots.txt (app/robots.ts): permite indexar todo lo público, bloquea /admin y /api/admin, y declara el sitemap.
  4. Schema.org (JSON-LD): la home inyecta un <script type="application/ld+json"> con WebSite + un ItemList de TouristAttraction (una por localidad activa, con dirección, coordenadas, audio como AudioObject y enlace externo cuando existe). Se construye en buildHomeJsonLd() (lib/seo.ts) a partir de la misma consulta que ya alimenta el mapa, reutilizando pickLocalized() (extraída de components/Map.tsx a lib/locality.ts para no duplicar la regla de fallback ES→EN/FR).
⚠ Pendiente relacionado: páginas propias por localidad

Ni el sitemap ni el JSON-LD pueden enlazar cada pueblo a su propia URL porque hoy no existe: las localidades solo se muestran como popups dentro del mapa de la home. Crear una página individual por localidad (p. ej. /pueblo/[slug]) permitiría que cada una posicionara en Google por su propio nombre — una mejora de SEO real, pero mayor que el alcance de B8. Además, a fecha de esta actualización el proyecto aún no tiene localidades reales cargadas (solo datos de prueba), así que tiene sentido esperar a que haya contenido real antes de acometerlo. Añadido como pendiente en el apartado 10.5.

10.2 — Google Analytics 4

  1. Crear la propiedad GA4 en analytics.google.com (a nombre de la promotora) y obtener el ID G-XXXXXXXXXX.
  2. Añadir NEXT_PUBLIC_GA_ID en Vercel (Production, Preview, Development) y redesplegar. El componente de banner de cookies ya está cableado para cargar GA4 solo tras consentimiento.
  3. Verificar en Google Tag Assistant que el evento page_view se dispara y que NO se dispara hasta que el visitante acepta cookies.

10.3 — Buzón propio en Hostinger (opcional)

Hoy noreply@tunomeolvides.es se usa solo para enviar (vía Resend). Si en algún momento se quiere recibir respuestas o tener info@ / contacto@ como buzón real:

  1. Activar el plan de email de Hostinger (suele ser unos 0,99 €/mes).
  2. Crear los buzones deseados. Hostinger ya tiene los registros MX/SPF/DMARC/DKIM preparados en el dominio raíz, así que no hay que tocar DNS para esto.
  3. (Opcional) Cambiar el Sender email de Supabase de noreply@ a info@ si se prefiere que las respuestas a invitaciones lleguen a un inbox real.

10.4 — Operativa continua

  • Vigilar el consumo de Resend (3000 emails/mes en free tier). El proyecto está muy por debajo, pero conviene revisar el dashboard de Resend cada cierto tiempo.
  • Vigilar el consumo de Supabase free tier (500 MB de base de datos, 1 GB de Storage, 50.000 usuarios autenticados/mes).
  • Renovar el dominio en Hostinger anualmente. Activar autorrenovación si está disponible.
